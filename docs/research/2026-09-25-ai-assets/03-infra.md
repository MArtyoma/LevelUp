# 03. Инфраструктура: загрузки и обновление ComfyUI (25.09.2026)

## Загрузки (~50 ГБ с Hugging Face, ~10 МБ/с)

- `curl: (92) HTTP/2 stream reset` посреди файла → скрипт падал. Лечение: `--http1.1`,
  `--retry-all-errors`, докачка `-C -`.
- Скорость одного файла падала до 20 КБ/с и не восстанавливалась. Лечение:
  `--speed-limit 500000 --speed-time 30` — curl сам переподключается.
- Энкодер MiniMax (16,7 ГБ): полный GET висел больше 5 минут без единого байта, а
  запрос с `Range` к тому же URL отдавал сразу, 6,8 МБ/с. Видимо, CDN xet собирает
  большой файл целиком перед отдачей. Лечение: первый мегабайт — `curl -r 0-1048575`,
  дальше `-C -` всегда шлёт Range. Внесено в оба установщика.
- Фоновый процесс через `nohup ... &` в SSH-сессии погиб вместе с ней. Надёжно:
  `systemd-run --unit=... --collect`.
- `pkill -f install_audio.sh` убил и собственную SSH-сессию (имя было в её командной
  строке). Не использовать `pkill -f` по строке, которая есть в собственной команде.

## ComfyUI 0.31 → 0.37

Нужно для MiniMax Music 3 (≥ 0.33). Образ kyuz0 не пересобирался с 11.08 — скачать
новее нечего. Собран свой поверх kyuz0 (`/srv/projects/vault/host/comfyui.Containerfile`
на arrakis), ROCm/torch не тронуты. Три неудачные сборки, все на моих проверках, не на деле:

1. `sd-bus ... interactive authentication` — сборке нужен `DBUS_SESSION_BUS_ADDRESS` worker;
2. в образе нет `diff`, потом нет `cmp` → сравнение через `test "$(cat a)" = "$(cat b)"`;
3. `import comfy.model_management` ищет GPU при импорте → при сборке GPU нет.

Первый запуск после переключения оказался на старом образе: служба поднялась за минуту
до установки новой обёртки. Проверять версию после перезапуска (`/system_stats`),
а не верить, что `start` что-то перезапустил.

Проверено на 0.37: графы imgd (vault) из `draw.py` — рисование и правка; klein + LoRA;
Stable Audio 3; ACE-Step. Откат — одна команда (в Containerfile и `/srv/docs/08-workloads.md`).
