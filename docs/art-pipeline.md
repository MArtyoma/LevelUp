# Генерация спрайтов нейросетью

Как получить черновик спрайта для LevelUp одной командой — и что с ним делать дальше.
Написано и для человека, и для ИИ-агента: всё, что нужно, чтобы начать, — в разделе
«Быстрый старт», остальное — когда что-то пошло не так.

Проверено 25.09.2026 на arrakis. Время ниже — оттуда же.

## Главное правило

**Сгенерированный спрайт — черновик для художника команды (artist), а не замена его работе.**
Арт — его зона: палитру, размер персонажа и то, что попадает в игру, решает он. Агент кладёт результаты в `art_out/` и показывает; в `assets/`
файл попадает, только когда человек сказал «берём этот».

Исключение — места, где сейчас стоят заглушки (`*_placeholder.png`): черновик лучше
заглушки, но его имя тогда тоже с `_placeholder`, чтобы было видно, что он временный.

## Быстрый старт

```bash
cd game
# персонаж 16x32, четыре варианта
python3 tools/art/gen_sprite.py npc_hr "young woman, HR manager, red cardigan, white blouse, dark skirt, holding a blue folder"

# предмет 16x16
python3 tools/art/gen_sprite.py plant "potted office plant, ficus in a white pot" --kind prop

# тот же персонаж со спины / сбоку / в другой одежде
python3 tools/art/gen_sprite.py npc_hr_back "the same character seen from behind, back view, facing away from the viewer" \
    --ref art_out/npc_hr/raw_02.png
```

Результат — в `art_out/<имя>/` (каталог в `.gitignore`):

| Файл | Что это |
|---|---|
| `sheet.png` | **Смотреть сюда.** Все варианты рядом: спрайт увеличенный на шахматке + исходник модели |
| `sprite_NN.png` | Готовый спрайт под сетку игры (RGBA, прозрачный фон) |
| `raw_NN.png` | Что нарисовала модель, 512×512. Его же подают в `--ref` |
| `meta.json` | Промпт, зерно, все параметры — чтобы повторить ровно этот результат |

Выбрали вариант — копируйте: `cp art_out/npc_hr/sprite_02.png assets/sprites/npc_hr.png`.

**Агенту:** после генерации откройте `sheet.png` (он один на весь набор) и оцените варианты
сами, прежде чем показывать человеку. Плохой набор — перегенерировать с другим `--seed`
или поправить описание, а не отдавать как есть.

## Требования

- Python 3 и Pillow (`pip install Pillow`) — больше ничего на своей машине.
- Сеть до arrakis (`192.168.1.202:8188` — ComfyUI; порт открыт для 192.168.1.0/24 и VPN 10.10.10.0/24).
- ComfyUI на arrakis **спит**, если 3 минуты никто не рисовал (так задумано — см. «Почему спит»).
  Будить:
  - есть SSH-ключ на arrakis — задать `COMFY_WAKE_CMD="ssh root@192.168.1.202 systemctl start comfyui"`,
    генератор разбудит сам (подъём ~12 с);
  - ключа нет — попросить человека выполнить на arrakis `systemctl start comfyui`,
    либо открыть в браузере `http://192.168.1.202:8188` после этого.

## Как писать описание

Описание — **по-английски**, через запятую: кто, одежда, одна-две приметы, что в руках.
Генератор сам дописывает слова-триггеры стиля, ракурс и фон — их писать не надо.

- Хорошо: `middle-aged man, CEO, grey suit, red tie, grey beard, holding a phone`
- Плохо: `начальник отдела` (русский), `a very important boss who is angry about KPIs` (сюжет вместо внешности)

Что уже проверено:

- **Персонажи рисуются «чиби», минималистично**: большая голова, короткое тело, глаза-точки,
  толстый тёмный контур, плоские цвета — это заложено в `--kind character`. При обычных
  пропорциях в 16×32 фигура выходит шириной 8 px, а лицо — три пикселя; детальные глаза
  при уменьшении превращаются в чёрные пятна, точки — остаются точками.
- **Одна яркая примета на персонажа** (красный кардиган, зелёная толстовка, наушники) — то,
  что переживает уменьшение. Мелочь (серёжки, значок, узор) пропадает всегда.
- **Фон.** Модель рисует на ядовито-зелёном, потом он вырезается. Если в описании есть
  зелёное (`green`, `plant`, `tree`...), генератор сам берёт пурпурный фон. Вручную: `--bg magenta`.
- **Ракурсы и варианты** — через `--ref` (режим правки): модель держит фигуру и стиль образца
  и меняет то, что сказано. Проверено: вид со спины, вид сбоку в шаге, смена одежды.
  Для `--ref` описание — это *изменение*: `the same character but ...`.
- **Вид вправо** не генерируйте: отразите вид влево (`ImageOps.mirror` или в Aseprite).
- **Предметы 16×16 — как значки, с обводкой.** С обычным описанием (`server rack with
  blinking lights`) сервер, сейф и кофемашина выходят тёмными кляксами. Работает дописать
  `simple minimalist low-res icon, thick dark outline, flat colors, few colors, big simple
  shapes, front view` и флаг `--outline`: так сделаны все предметы в `assets/props/`
  (25.09.2026, зёрна 201–216). Диван и стопка бумаг даже так читаются плохо — такое проще
  нарисовать руками. Предмет на стену генерируйте сразу меньше (`--size 14x10`), чтобы
  под ним остался виден плинтус.

## Параметры

| Флаг | По умолчанию | Когда менять |
|---|---|---|
| `--kind character\|prop\|portrait` | `character` | Задаёт размер, ракурс и якорь (персонаж — ногами к нижнему краю, остальное — по центру) |
| `--size WxH` | 16x32 / 16x16 / 32x32 | Если artist решит иначе (D-011: персонажи 16×16 или 16×32) |
| `--count` | 4 | 1–8; все варианты за один проход, это дешевле, чем по одному |
| `--seed` | случайное | Повторить результат — взять из `meta.json` |
| `--ref FILE` | — | Режим правки по образцу (лучше `raw_NN.png`, не спрайт) |
| `--palette FILE` | `assets/palette.hex`, если есть | Палитра проекта; без неё подбирается своя на каждый спрайт |
| `--colors` | 16 | Сколько цветов, когда палитры нет |
| `--outline` | нет | Тёмная обводка в 1 px: фигура лучше отделяется от пола, но сама на 2 px меньше (14×30) |
| `--bg green\|magenta` | авто | Цвет фона-хромакея |
| `--lora` | 1.0 | Сила пиксельной LoRA, 0 — без неё. Выше 1.3 не проверяли |
| `--raw-prompt` | нет | Промпт уходит как есть, без триггеров и фона |

Постобработку можно запустить отдельно на любой картинке (например, на арте из другого места):

```bash
python3 tools/art/pixelize.py some.png out.png --size 16x32 --chroma green --preview
```

## Палитра

`assets/palette.hex` — **черновик** на 24 цвета (Sweetie 16 + кожа, дерево, волосы, пол,
лиловый), утверждает художник команды. Генератор приводит к ней все спрайты сам; тот же
файл читают `tools/art/draw_tiles.py` и `make_portrait.py`, поэтому поменяли цвет в нём —
перегенерировали — и он поменялся везде. Формат Lospec: строка — цвет `RRGGBB`, `;` — комментарий.

Другая палитра на один запуск: `--palette путь.hex`. Без файла палитры спрайт получил бы
собственные 16 цветов (`--colors`) и не сочетался бы с остальными.

## Чего ждать и чего не ждать

**Хорошо получается:**
- исходник 512×512 — чистый пиксель-арт «чиби», годится как референс для рисования руками;
- 16×32 — узнаваемый силуэт: причёска, основной цвет одежды, предмет в руках;
- 16×16 предметы — узнаваемы (растение, кружка, кулер);
- серия одного персонажа в разных ракурсах через `--ref`.

**Плохо или никак:**
- лицо в 16×32 — 3–4 пикселя; очки и детальные глаза — чёрные пятна (промпт с глазами-точками это смягчает);
- дырки там, где рука близко к телу (просвет фона уходит в прозрачность);
- **кадры анимации** — не рисует, только позы; простой шаг собирает `make_sheet.py`;
- **тайлы**, стыкующиеся краями, — не делает; для них `draw_tiles.py` (кодом);
- одинаковая палитра между спрайтами — только через `assets/palette.hex`.

Реалистичная цена: черновик спрайта — минута, доводка руками в Aseprite — 10–15 минут
вместо часа рисования с нуля.

## Как это устроено

```
ваша машина                                    arrakis (192.168.1.202)
─────────────────────────────                  ──────────────────────────────────────
gen_sprite.py ──HTTP :8188──────────────────►  ComfyUI (служба comfyui, контейнер ROCm)
  граф: FLUX.2 klein 4B + LoRA, 4 шага           models: /srv/models/comfy
  ◄── raw 512×512 (PNG) ─────────────────────   output: /srv/work/comfy-out/levelup/
pixelize.py
  1. фон: заливка от края по оттенку хромакея + обдирка зелёной каймы
  2. обрезка по фигуре
  3. палитра: каждый пиксель -> ближайший цвет assets/palette.hex по Lab
  4. сетка: клетка = самый частый цвет; у персонажей тёмное (контур, глаза) побеждает,
     если его в клетке >= 25%; прозрачность — если фона больше половины
  └► sprite_NN.png + sheet.png + meta.json
```

**Модели** (все лежат в `/srv/models/comfy` на arrakis):

| Файл | Что | Лицензия |
|---|---|---|
| `diffusion_models/flux-2-klein-4b.safetensors` | FLUX.2 [klein] 4B, bf16, дистиллят на 4 шага | Apache 2.0 |
| `text_encoders/qwen_3_4b.safetensors` | текстовый энкодер klein | Apache 2.0 |
| `vae/flux2-vae.safetensors` | VAE FLUX.2 | Apache 2.0 |
| `loras/pixel-art-sprite-klein4b-fixed.safetensors` | [Limbicnation/pixel-art-lora](https://huggingface.co/Limbicnation/pixel-art-lora), обучена на CC0 | Apache 2.0 |

Всё с разрешённым коммерческим использованием: если игру когда-нибудь выложат, лицензии
не помешают. bf16, а не fp8, потому что у gfx1151 нет аппаратного fp8.

**Граф** повторяет официальный шаблон ComfyUI «Flux.2 Klein 4B Distilled»: `UNETLoader` →
`LoraLoaderModelOnly` → `CFGGuider` (cfg 1, негатив — `ConditioningZeroOut` от позитива) →
`SamplerCustomAdvanced` (euler, `Flux2Scheduler` 4 шага) → `VAEDecode`. С `--ref` образец
кодируется `VAEEncode` и цепляется к обоим условиям через `ReferenceLatent`. Собирается
в `build_graph()` в `gen_sprite.py`.

**Замеры (arrakis, рядом работает языковая модель):** 4 варианта 512×512 — 12–16 с
(из них ~8 с — чтение весов, ComfyUI отдаёт их после каждого задания); подъём из сна — ~12 с;
постобработка на ноутбуке — ~1,5 с на картинку.

## Соседние инструменты

Генератор даёт отдельные позы. Остальное для игры — отдельные скрипты в `tools/art/`:

| Скрипт | Что делает |
|---|---|
| `make_sheet.py` | Лист ходьбы 4×4 (вниз, влево, вправо, вверх) из поз спереди/сбоку/сзади: в кадрах шага поднимает ногу на пиксель. Вправо — зеркало влево. NPC — `--idle`: одна поза и кадр «вдоха» (плечи и голова ниже на пиксель), `npc.gd` листает их таймером |
| `make_portrait.py` | Портрет для окна диалога из того же `raw_NN.png`, что и спрайт, — чтобы это был тот же человек |
| `draw_tiles.py` | Атлас тайлов офиса **кодом** по палитре: нейросеть бесшовные тайлы не умеет. Ряды 2–3 — предметы отделов: вклеиваются из `assets/props/<имя>[_placeholder].png` |

Цепочка для нового предмета: `gen_sprite.py --kind prop --outline` → выбранный
`sprite_NN.png` в `assets/props/<имя>_placeholder.png` → клетка в `PROPS` у `draw_tiles.py`
и строка в `TILES` у `tools/build_tileset.gd` (коробка столкновений) → куда поставить —
`decor` кабинета в `tools/build_demo_level.gd`.

Цепочка для нового NPC: `gen_sprite.py` (спереди) → при нужде `--ref` (сбоку, сзади) →
`make_sheet.py` → `make_portrait.py` из того же raw. Подробности — в docstring каждого скрипта.

## Почему именно так (решения, которые не надо принимать заново)

- **Модель.** FLUX.2 klein 4B + пиксельная LoRA выбраны 25.09.2026 из FLUX.2 klein 4B/9B,
  Krea 2, Qwen-Image 2.1: Apache 2.0, 4 шага (быстро), умеет править по образцу.
  Qwen-Image 2.1 (20.09.2026) рисует настоящую прозрачность, но лицензия только
  некоммерческая, 40 шагов и пиксельных LoRA под неё пока нет — пересмотреть позже.
- **LoRA «fixed».** В оригинальном файле 6 ключей модуляции названы по-diffusers, и ComfyUI
  молча их пропускал (в логе `lora key not loaded: double_stream_modulation_img.linear...`).
  `tools/art/fix_lora.py` переименовывает их в формат ComfyUI. Сравнение на одном зерне:
  с полной LoRA заливка площе и меньше бликов — то, что лучше переживает уменьшение.
- **«Прозрачный фон» из карточки LoRA не используем.** Модель рисует вместо прозрачности
  шахматку, и её не отличить от светлой одежды. Сплошной ядовитый фон вырезается чисто.
- **Уменьшение — «самый частый цвет клетки»**, а не усреднение: сравнивали на одних
  исходниках, усреднение даёт грязь, частый цвет — чистые плоские пятна. Тонкий тёмный
  контур и глаза при этом пропадали — поэтому тёмное получает приоритет (`dark_share=0.25`),
  но **только у персонажей**, у которых промпт в упрощённом стиле: на детальных исходниках
  очки и волосы уходят в сплошное чёрное. У `prop` и `portrait` приоритет выключен.
- **Палитра — по Lab, попиксельно, а не по RGB.** По RGB красный кардиган уходил в оранжевый,
  голубая рубашка — в серый, чёрные волосы — в тёмно-синий.
- **Почему спит.** Torch на ROCm после первой картинки навсегда занимает ядро процессора
  (~28 Вт и шум вентиляторов), лечится только остановкой процесса. Поэтому ComfyUI гасится
  через 3 минуты простоя и поднимается по требованию. Подробно — `/usr/local/bin/comfy-idle`
  на arrakis.

## Неполадки

| Симптом | Причина и что делать |
|---|---|
| `ComfyUI на ... не отвечает (скорее всего спит)` | Разбудить, см. «Требования» |
| `ComfyUI вернул ошибку: ... not in list` | Нет файла модели на arrakis — переставить: `tools/art/install_arrakis.sh` |
| `ComfyUI вернул ошибку: ... out of memory` | Рядом загружена языковая модель, памяти впритык. Уменьшить `--count`; при повторе — сказать человеку, не крутить в цикле |
| Фигура с дырами/без куска одежды | Этот цвет совпал с фоном: `--bg magenta` (или наоборот `green`) |
| Зелёная/розовая кайма по краю | Поднять допуск: `--bg-tol 80` |
| В логе ComfyUI `lora key not loaded` | Взят не тот файл LoRA — нужен `...-fixed.safetensors` |
| Всё фото-реалистичное, а не пиксельное | Не дописались триггеры: не используйте `--raw-prompt` без нужды |

Лог ComfyUI на arrakis: `runuser -u worker -- env XDG_RUNTIME_DIR=/run/user/1000 podman logs --tail 100 comfyui`.

## Установка с нуля

Если arrakis переустановили или модели пропали:

```bash
scp tools/art/install_arrakis.sh tools/art/fix_lora.py root@192.168.1.202:/srv/work/
ssh root@192.168.1.202 bash /srv/work/install_arrakis.sh
```

Скрипт качает ~16,5 ГБ, сверяет sha256, докачивает при обрыве и сам делает `-fixed`-копию
LoRA. Повторный запуск безопасен. ComfyUI должен быть не старше 0.31 (FLUX.2 klein);
сборка образа ComfyUI описана в `/srv/projects/vault/host/comfyui.Containerfile` на arrakis.
