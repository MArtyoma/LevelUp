# Как устроена игра

*Документ для тех, кто пишет код: лид и artist. Обновляется вместе с кодом.*

## Одно решение, из которого следует всё остальное

**В коде нет содержания игры.** Ни одного имени сотрудника, ни одной реплики, ни одного
квеста. Всё это лежит в `data/*.json`; код — это оболочка, которая умеет показать *любую*
компанию.

Решение записано как D-003 в `../../docs/decisions.md` и принималось ради персональных данных
заказчика, но оказалось важнее: из него следует почти вся остальная архитектура.

| Следствие | Что это даёт проекту |
|---|---|
| writer пишет легенду и диалоги в JSON | человек без опыта разработки производит содержание игры, не открывая редактор кода |
| level designer ставит NPC и вписывает `employee_id` | левел-дизайн без единой строки кода |
| Данные проверяются скриптом | ошибка ловится за 5 секунд в CI, а не за неделю до защиты на плейтесте |
| Подмена папки данных — другая компания | реальные ФИО заказчика никогда не попадают в репозиторий |
| Игра одинаково стартует у всех участников замера | иначе на неделе 9 нечем объяснить разброс цифр |

## Слои

```
        данные                 состояние              представление
   ┌───────────────┐      ┌─────────────────┐     ┌──────────────────┐
   │   GameData    │      │    QuestLog     │     │    GameUi        │
   │  company.json │      │ DialogueRunner  │     │   DialogueBox    │
   │ dialogues.json│      │   Telemetry     │     │  Player, Npc     │
   │  quests.json  │      │    SaveGame     │     │   AccessDoor     │
   └───────┬───────┘      └────────┬────────┘     └─────────┬────────┘
           │  читают                │  сигналы              │
           └────────────────────────┴───────────────────────┘
                              EventBus
```

Правило, на котором всё держится: **вниз — вызовы, вверх — сигналы.** Представление читает
данные и состояние напрямую, но менять их может только через методы; состояние о представлении
не знает вообще и кричит в `EventBus`.

Что это даёт практически: панель квестов можно переписать с нуля, не открывая ни одного файла
с игровой логикой, и наоборот. Код пишут двое — граница между ними проходит ровно по `EventBus`.

## Автозагрузки: почему именно эти пять с половиной

Автозагрузка — глобальный объект, и их легко развести десяток, после чего в проекте не остаётся
ни одного места, о котором можно сказать «состояние живёт здесь». Поэтому список закрыт, и каждая
позиция в нём отвечает на вопрос «что сломается, если её не будет».

* **EventBus** — без него системы начнут держать ссылки друг на друга.
* **GameData** — данные читаются один раз; иначе каждая реплика лезла бы в файл.
* **QuestLog** — единственное место состояния прохождения.
* **DialogueRunner** — разговор идёт поверх любой сцены и переживает переходы.
* **Telemetry** — подписана на всё сразу, ничего не зная о подписчиках.
* **SaveGame** — тонкая обёртка над QuestLog, отдельная только потому, что формат файла
  меняется чаще, чем состояние.

Новая автозагрузка добавляется через разговор с лидом, а не молча.

## Что сделано ради скорости

Игра маленькая, и «оптимизация» здесь — это не микросекунды, а решения, которые не дают
проекту деградировать по мере роста.

1. **Рендер — `gl_compatibility`.** Игра запускается на слабых ноутбуках и встроенной графике,
   а именно на них будет проходить замер на неделе 9. Vulkan там местами просто не стартует.
2. **Окно 480×270, растяжение `canvas_items` + целочисленный масштаб.** Мир рисуется в родном
   разрешении и увеличивается целым числом раз — на 1920×1080 ровно ×4. Никакого зума камеры:
   дробный зум даёт дрожащие пиксели, которые невозможно «починить» потом.
3. **Спящие узлы.** У NPC, дверей и предметов `_process` и `_physics_process` выключены. Они
   реагируют на события, а не опрашивают мир каждый кадр. Двенадцать спящих NPC вместо
   двенадцати работающих — мелочь; тридцать таких мелочей — уже разница.
4. **Поиск по словарю, а не по списку.** `GameData` строит индексы один раз при загрузке.
   Диалог дёргает `get_employee()` на каждой реплике — там перебор массива недопустим.
5. **Взаимодействие через физику, а не через перебор.** Игрок не считает расстояние до всех
   NPC каждый кадр: список «до кого можно дотянуться» наполняет сигналами `Area2D`, и он почти
   всегда пуст.
6. **Таймер дуэли включается только на время дуэли** (`set_process(true/false)`).
7. **Один спрайт человека на всех**, цвет — из данных через `modulate`. Пятнадцать сотрудников
   без пятнадцати рисунков; для команды с двумя-тремя художественными часами в неделю это
   не украшение, а условие выживания.

## Чего здесь сознательно нет

Записано, чтобы не пришлось объяснять это заново на пятой неделе.

* **Нет ECS и нет менеджера менеджеров.** Объём v1 — один этаж, 12 NPC, 5 квестов. Архитектура
  под миллион сущностей стоила бы больше, чем сама игра.
* **Нет графа зависимостей между шагами квеста.** Шаги идут по порядку. Когда понадобится
  ветвление — добавим, а пока это лишняя сложность в том месте, где тексты пишет новичок.
* **Нет собственного формата данных и нет редактора данных.** JSON правится блокнотом,
  ошибки ловит валидатор. Админка вынесена за границы v1 уставом.
* **Нет сетевого кода, сохранения в облако, достижений.** См. «Не входит в v1» в уставе.
