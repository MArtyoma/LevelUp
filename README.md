# LevelUp

Игра-симулятор первого дня в новой компании. Игрок — новый сотрудник: ходит по офису,
знакомится с людьми, выполняет поручения и по ходу дела понимает, кто чем занимается и к кому
идти с каким вопросом.

Учебный проект. Проверяем гипотезу: **интерактивная симуляция офиса помогает новичку запомнить
структуру компании лучше, чем обычная welcome-презентация при том же времени.** Замер — на
двух группах по 6–8 человек, тест из 10 вопросов сразу после и через 2–3 дня.

Устав, план по неделям и журнал решений — в отдельном репозитории с документацией.

## Запустить

1. Поставить **Godot 4.7.2** — https://godotengine.org/download (одна папка, установка не нужна).
   Версия важна: сцены, сохранённые более новым редактором, в более старом не открываются.
2. `git clone` этого репозитория.
3. В Godot → **Import** → выбрать `project.godot` из папки репозитория.
4. **F5**.

Управление: **WASD** или стрелки — ходить, **E** — говорить и брать, **J** — журнал заданий,
**Esc** — выход.

## Команды

```bash
# Проверить данные в data/ — ошибки печатаются по-русски с номером строки
godot --headless --script tools/validate_data.gd

# Прогнать тесты (44 штуки, около ста миллисекунд)
godot --headless res://tests/test_runner.tscn

# Снять скриншот запущенной игры (для письма заказчику и отчёта)
godot --screenshot=shot.png --screenshot-frame=120 res://tools/screenshot.tscn

# Запустить на данных заказчика, которых нет в репозитории
godot --data-dir=../private-data

# Записать прохождение участника эксперимента под его кодом
godot --participant=B07
```

После смены размера тайла в настройках проекта (`levelup/grid`):

```bash
python3 tools/make_placeholder_art.py                     # перерисовать заглушки арта
godot --headless --script tools/build_tileset.gd          # пересобрать тайлсет
godot --headless --script tools/rescale_level.gd -- --from=16 --to=32   # подвинуть NPC на карте
```

## Размеры спрайтов

Размер тайла и размер кадра персонажа задаются в одном месте:
**Проект → Настройки проекта → Основные → `levelup/grid`.**

```
tile_size                16, 32, 64 — размер тайла в пикселях
character_frame_width    ширина кадра в листе персонажа
character_frame_height   высота кадра. Больше ширины — нормально:
                         16x32 значит, что голова торчит над линией тайла
walk_frames              кадров в цикле ходьбы
visible_tiles_x/y        сколько тайлов помещается на экран
```

Всё остальное — коробки столкновений, радиус взаимодействия, смещение спрайта, положение
подписи над головой, размер окна, скорость ходьбы, размеры интерфейса — считается из этих
чисел (`src/core/grid.gd`). В коде нет ни одного размера в пикселях, и это проверяют тесты
на 16, 32 и 64 сразу.

Два обещания, которые при этом держатся: на экран влезает **одинаковое число тайлов**,
а игрок проходит комнату **за то же время** — прохождение должно укладываться в 10–15 минут
при любом размере, иначе не с чем сравнивать контрольную группу.

## Правила, которые здесь закреплены не на словах

* **Никаких имён и текстов в коде.** Всё содержание — в `data/*.json`. Реальные ФИО и должности
  заказчика в репозиторий не попадают никогда: они лежат во внешней папке, а `.gitignore`
  не пускает их внутрь.
* **У каждой сцены `.tscn` один владелец.** Git мирит сцены Godot плохо; `.gitattributes`
  запрещает автослияние, `CODEOWNERS` зовёт владельца в pull request.
* **Сломанные данные не попадают в `master`.** Проверка и тесты гоняются на каждый push
  (`.github/workflows/ci.yml`). Красная галочка означает «чиним, потом сливаем».
* **Всегда есть запускаемый билд.** Приехал заказчик — есть что показать. Всегда.
